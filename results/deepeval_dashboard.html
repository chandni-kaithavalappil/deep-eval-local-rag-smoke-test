Experiment Story

1

Original benchmark

Build a full LightRAG index over the corpus, then run handcrafted and synthesized DeepEval suites.

2

Local bottlenecks

OpenAI quota blocked cloud ingest. Qwen embeddings timed out locally. Nomic embeddings worked, then Granite graph extraction timed out.

3

Scope pivot

The goal became a metric demo, so the run moved to one document, vector-only retrieval, and one metric at a time.

4

Demo complete

DeepEval now reports useful scores and exposes a concrete story: decent answers, weak context, near-pass grounding, strong refusal behavior.

What the scores mean

This was not a polished RAG system trying to maximize score. It was a diagnostic slice. The useful result is the pattern: answers are often relevant and somewhat faithful, but the vector-only context is too broad and the second answer hallucinated ASL-4 instead of the ASL-3 deployment commitment.

Demo Takeaways

DeepEval loop works locally

Focused metrics can complete with Ollama when each run is small and context is capped.

Retrieval quality is the weak point

Contextual Relevancy averaged 0.278, showing the vector-only smoke index is useful for demos but not production evaluation.

Judge choice matters

The tiny local judge can score RAG metrics, but it may emit malformed JSON or misjudge GEval refusal prompts.
